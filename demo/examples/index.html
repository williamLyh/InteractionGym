InteractionGym example episodes

24 episodes · click a name for the environment view (all episodes are in its sidebar), "tokens" for the agent server trace.

Example episodes, generated 2026-10-10 on one 8-GPU host with InteractionGym 0190f8e (examples/minicpmo_suite.py; the chat set is --set chat). Agent: MiniCPM-o 4.5 full duplex on vLLM-Omni (audio out, input-clocked, 1 s steps). Simulated user: Qwen3.8-27B writes the turns and decides when to backchannel or barge in; Qwen3-TTS voices them (cloned from the first turn). First: casual conversation and everyday knowledge (6 in English, 5 in Mandarin), with the env’s realism on: recorded ambience of the caller’s surroundings (DEMAND), random noise events (MUSAN) and asides to someone nearby. Each of these is the best of 3 takes after an ASR check of every turn, and was fact-checked by an LLM judge (notes column). Then one offline replay (pre-timed caller turns with a barge-in, a backchannel and a noise).

Then 5 service calls with an SOP (2026-10-13, examples/sop_calls.py), same agent and user: a restaurant, a clinic and an online shop each have an SOP in InteractionGym’s SOP source format (conditions combined with all / any / in order; docs/SOP.md), shown to the agent in the structured format together with what it would see on its screen; it has no tools, so it must ask the caller for the rest. Some callers should be served, others declined (a party of ten that will not pay the deposit; a refund 44 days after delivery). After the call an LLM reports what happened and rules on the SOP tree score the decision, the procedure and the details (the SOP policy card shows the SOP, the screen and the ground truth; Evaluation → Content the report). Chosen to show both outcomes: 3 pass and 2 fail (a booking for ten without the deposit; a refund outside the 30-day window). Across all 12 takes, 5 passed; the refund was granted in all 3.

Last, three tool environments (2026-10-13) with a different agent: Qwen3.8-27B with tools, hearing the caller’s transcript and speaking through Qwen3-TTS. 2 computer use episodes (examples/browsergym_demo.py): browser tools on a real Chromium page (BrowserGym MiniWoB++), pre-timed caller turns, scored by the benchmark’s reward; move the cursor along the timeline to see the page in the state panel. 2 collaborative coding episodes (examples/colbench_demo.py): ColBench Backend Programming (SWEET-RL, Meta; CC BY-NC data, an output of Llama 3.1): the caller holds the hidden reference function and answers with ColBench’s simulator prompt, the agent asks and hands in the code with submit_code (click the call to read it), and the 10 hidden tests score it after the call. Picked among passing takes. 3 procedure-following episodes (examples/sopbench_demo.py): SOPBench (Li et al. 2025; data CC BY 4.0): the caller gives their details only when asked; the agent has SOPBench’s prompt and SOP and must verify the SOP’s conditions with function calls before it acts or declines; SOPBench’s verifier scores the calls and the final database. One case carried out, one correctly declined, and one failure the verifier catches (a booking the SOP forbids).
